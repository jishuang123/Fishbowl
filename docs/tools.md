# V0.10：本机时间插件与流式工具调用

重新运行 Fishbowl，在聊天中问“现在几点？”“今天几号？”或“今天星期几？”。大肥鱼会请求本机时间工具，绿色卡片显示查询结果，再继续流式回答。卡片包含完整日期、秒级时间、星期、系统时区名和 UTC 偏移。依据是这台电脑的系统时钟，不是联网校时或模型猜测。

使用现有本机 DeepSeek Key。插件不接收 Key、聊天历史或网页对象。只注册当前时间查询，无参数、只读；模型无法通过工具名或参数执行其他本机操作。

## 聊天、语音和记忆

- 模型以流式 `tool_calls` 请求工具。参数分片按调用索引拼合，收到有效结束标记后才执行。工具返回结果后，同一轮继续请求模型，仍使用流式输出。实现遵循 [DeepSeek 工具调用流程](https://api-docs.deepseek.com/guides/tool_calls/)和 [Chat Completions SSE 协议](https://api-docs.deepseek.com/api/create-chat-completion/)。
- 从用户发送到最终回复结束，始终视为同一次生成；“取消”在工具阶段和续答阶段都有效。45 秒为整轮总时限，工具返回不会重置计时。文本或调用中断时不写入本轮记忆。
- 绿色卡片与模型的解释分别显示。卡片、参数和中间过渡文字不会提前触发 TTS；最后完整回复统一触发原来的朗读流程，继续遵守静音和音量口型。工具查询不触发角色的点击或待机映射。
- 完整回复结束后，将卡片的展示信息附加到这一轮助手记忆。重启、切回角色会恢复已完成卡片，不重新查询、不自动重播语音。历史卡片只是过去的查询记录，当前时间问题必须再次调用工具。
- 后续新问题只发送原有 user/assistant 对话；历史 `tool_results` 不直接送入 API，上一轮工具协议也不重放。当前轮的 assistant 调用消息和 tool 结果只在本轮内存中保留。
- 取消、超时、关闭聊天、切换角色或续答请求失败，均不提交该轮工具记录。已执行的查询仍可在当前面板中看到，并标明“本轮未完成，不计入记忆”；清空记忆会一并移除卡片。
- 未注册工具、参数错误、插件异常均显示简短失败信息，供模型解释；不暴露异常正文、路径或原始服务错误。每轮最多 2 轮工具请求、4 次工具调用，达到限制后停止继续调用。单次工具参数最多 4096 字符，SSE 每段请求仍限制 1 MiB。

目前所有角色复用同一组只读内置工具，聊天记忆仍各自独立。本轮没有增加插件安装、外部脚本扫描或后台 Agent。

## 扩展接口

| 文件 | 职责 |
| --- | --- |
| `app/tool_registry.py` | `ToolPlugin` 定义、工具注册、API schema、参数校验及结果处理 |
| `app/plugins/__init__.py` | 显式列出当前应用启用的内置插件 |
| `app/plugins/current_time.py` | `get_current_time`，读取系统本地时间和时区 |
| `app/streaming.py` | SSE 中正文与工具调用分片的解析，不执行工具 |
| `app/chat.py` | 维护一次聊天的多段网络请求、调用限额、取消和最终提交 |
| `app/chat_window.py` | 原生结果卡，按纯文本显示，不增加网页权限 |

新插件实现 `ToolPlugin`，提供唯一 `name`、显示 `title`、描述、参数 schema、参数校验函数和 `handler`，再加入 `builtin_plugins()`。处理器返回字典，包含布尔 `ok` 和给用户看的非空 `display`；其他字段以 JSON 返回模型。当前处理器仅适合像时间查询这样快速完成的本机操作；长耗时或联网任务应先扩展异步执行机制，不能直接阻塞界面线程。

默认参数校验仅允许 `{}`；带参数插件必须提供与 schema 对应的校验函数。测试插件注册示例位于 `verify_tools.py`，不会自动安装到真实应用。当前模型仍使用关闭思考的非思考模式，未改成思考模式工具链。
