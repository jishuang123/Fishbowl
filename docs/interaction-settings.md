# V0.9：不用编辑 JSON 的角色互动设置

运行 Fishbowl，右键桌宠或托盘，选择「角色互动设置…」。窗口标题显示当前角色，只修改这个角色的映射。

三页分别对应「点击头部」「点击身体」「随机待机」。每页可选：

- **保留角色默认互动**：继续使用角色配置中的行为。大肥鱼默认头部轮换脸红、爱心眼、开心眼，身体使用完整抚胸手势，待机低频随机表情或手势。
- **自定义**：分别选择一个动作、一个表情和一段语音，可以组合，也可以将其中某项设为“无”。随机待机使用所选组合，随机的是触发时间，当前不提供多个自定义组合的随机池。
- **关闭这个触发**：关闭该页对应的互动，鼠标拖动、跟随和聊天不受影响。

点击「保存」后立即生效，不重载模型，不取消聊天，不清空记忆或草稿。正在播放的互动动作/语音会停止，聊天朗读继续。点击「取消」放弃本次映射修改。「恢复默认」需要再点「保存」才应用。

## 动作和表情

列表来自当前模型资源。大肥鱼保留经过筛选的完整抚胸动作，并额外列出包内原始动作和表情；导入角色列出 `.model3.json` 注册的动作和表情。原始资源名称可能简短或难懂，当前直接显示模型导出名，不自动推断含义。

普通动作临时改为播放一次，最长约 12 秒后停止；完成或被打断后恢复动作拥有的参数及部件透明度，不把视线、物理和嘴部状态固化到默认姿势。完整抚胸动作仍按原来的“抬手、停留、回位”播放。表情持续约 2.5 秒，待机约 2 秒，然后恢复。额外原始动作/表情尚未逐个进行完整视觉验收。

默认动作保持原样。自定义随机待机仍每隔约 45–100 秒尝试触发，不补做错过的互动。按住、拖动、隐藏窗口、打开菜单或设置对话框会暂停或推迟待机；点击和拖动可以中断待机，不会排队补动作。手动动作播放中不会因重复点击重新开始。

## 语音与口型

可选择模型目录中的音频，或点击「导入音频…」复制一份本地 WAV、MP3、OGG，单文件不超过 32 MiB。导入后可用于这个角色的任一触发。导入不修改原文件；取消设置不删除已经导入的音频副本。

配置语音使用现有原生语音通道，因此保留音量口型和全局静音。静音立即停止播放，取消静音不会补播。文本正在生成、聊天 TTS 正在准备或朗读时，跳过互动语音，不会打断回复，也不补播。开始新聊天仍会停止旧语音。点击或拖动立即停止待机语音；手动触发可替换旧手动语音。

口型在表情更新后、物理更新前应用，让音频驱动嘴部的优先级高于嘴部表情，并继续驱动下颌物理。没有相应嘴部参数的模型仍只能播放声音。

## 本机保存位置

用户目录为 `%LOCALAPPDATA%\Fishbowl\Fishbowl\`：

| 路径 | 内容 |
| --- | --- |
| `interactions/<角色 ID>.json` | 每个角色的三个触发映射；原子保存 |
| `interaction-audio/<角色 ID>/` | 本机导入的音频副本 |
| `memories/<角色 ID>.json` | 原有角色记忆，设置界面不修改 |
| `settings.json` | 原有全局静音和当前角色，不与映射混写 |
| `deepseek.json` | 原有 API 配置，不进入网页或角色映射 |

网页只收到选中动作的播放描述、表情名和“是否配置语音”的标记，不接收用户音频绝对路径、Key 或聊天记忆。新导入角色默认继续使用其原有行为，不继承大肥鱼的自定义设置。映射损坏或引用丢失时回到默认并在设置窗口提示；保存失败时对话框保留修改，不能虚报成功。

## 验证

`tools/verify_mappings.py` 在真实 Chrome、真实模型上检查自定义头部表情、单次原始动作及恢复、低频待机、点击/拖动优先、关闭触发后重新加载仍生效。使用 Playwright 时钟加快等待，不替换 Live2D。

`tools/verify_mappings_ui.py` 实际操作原生设置、音频选择器及按钮，检查角色隔离、保存/取消/恢复默认、重启读取、流式聊天不断流、真实音频解码与口型、静音、待机语音被拖动停止、聊天 TTS 优先，以及 Haru 的强制张嘴表情仍服从音频口型。

截图和结果位于 `.local/evidence/mappings/`。聊天使用本地 SSE 测试回复，系统 TTS 和音频解码实际运行但输出音量为零；不验证真实 DeepSeek 回答、声音听感、所有第三方模型或所有音频编码。
