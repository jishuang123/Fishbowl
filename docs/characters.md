# V0.8：角色包、导入与独立记忆

右键桌宠或托盘，选择「切换角色」。大肥鱼始终保留在菜单中。选择「导入 Live2D 模型…」，打开完整、已解压模型目录里的 `.model3.json`；成功导入会自动切换。当前入口不直接导入 ZIP、PSD 或旧 `.model.json`。

导入在后台复制模型引用的文件，不修改源目录。检查 Moc、贴图、动作、表情和可选物理/姿势文件是否齐全，拒绝目录越界、无效格式及总计超过 512 MiB 的资源。检查通过仍不保证所有 Cubism 模型都兼容；实际渲染失败或 45 秒未完成时返回之前的角色。程序记住最后一个成功显示的角色，重启恢复。

项目只预置大肥鱼配置，不分发新角色素材。验收使用本机官方 SDK 的 Haru，导入到临时目录，测试结束清理，不写入个人角色目录。

## 配置在哪里

- `characters/deepseek/character.json`：大肥鱼的源模型入口、资源准备规则、跟随/口型参数、点击/待机表情与手势。准备脚本和运行时都读取此配置。
- `characters/deepseek/persona.txt`：大肥鱼人格，与渲染和网络代码分开。
- `characters/generic.json`：新导入模型的通用渲染配置模板。
- `%LOCALAPPDATA%\Fishbowl\Fishbowl\characters\<角色 ID>\`：本机导入包，包含 `character.json`、`persona.txt` 和 `model/` 资源。ID 自动生成，同名角色仍各自独立。
- 同一用户目录的 `memories/<角色 ID>.json`：每个角色最近 10 轮完整对话。
- 同一用户目录的 `settings.json`：全局静音及当前角色；`deepseek.json`：全局 API 配置，仍仅保存在本机。

旧版 `chat-memory.json` 只迁移给大肥鱼，其他角色从空会话开始。目标记忆已存在时不覆盖。切换会恢复角色自己的气泡和本次运行的未发送草稿；“清空记忆”只清空当前角色。切换会取消旧角色的流式请求、未完成气泡和语音，不把半截回复写入任何角色。旧角色已完成的对话保留。

## 导入角色如何配置互动

新模型保留原 `.model3.json` 的 Idle 动作、表情和物理资源，但不自动套用大肥鱼的抚胸、脸红或爱心眼。V0.9 起，直接通过右键的「角色互动设置…」选择模型中的动作、表情和语音，无需手动编辑文件，见 [设置界面](interaction-settings.md)。默认启用标准 `ParamAngleX/Y/Z` 跟随、`ParamMouthOpenY` 近似口型；模型没有对应参数时不会产生预期动作，需要按实际参数调整。头部点击仍按画布上部 35% 可见像素判断。

以下为高级参数说明；普通点击/待机映射请使用界面，保存立即生效。高级参数仍通过导入包的 `character.json` 修改，改后重启应用。模型渲染入口在 `runtime.model_url`，必须位于该角色 `/character-assets/<角色 ID>/` 路径；人格文件通过 `persona` 指定相对包目录的文本路径。不要把 Key 写进角色配置。

`runtime` 的可调整字段：

| 字段 | 含义 |
| --- | --- |
| `tracking.x/y/z` | 模型接受头部跟随的参数 ID，大肥鱼使用 `AngleX/Y/Z` 驱动物理 |
| `mouth.open/jaw/jaw_scale` | 开嘴参数、可选下颌参数及倍率；不使用下颌时 `jaw` 留空 |
| `expressions.neutral/manual/idle` | 恢复表情名、头部点击轮换列表、低频待机列表；列表项须在模型中存在 |
| `gesture` | 可选的“进入 → 短暂停留 → 回位”动作对；不需要时为 `null` |
| `mask_buffers` | 遮罩缓冲数，大肥鱼需要 2 |
| `blink_while_motion` | 是否在动作播放时继续自动眨眼；仅对不控制眼睑的动作启用 |

`gesture` 中的 `group/enter/exit` 指模型动作组及进入、回位索引，`hold_ms` 为停留时长，`parameters` 列出动作拥有、结束后需恢复的参数 ID，`name` 为诊断名称。先用模型真实动作核对配置；不自动猜测动作是否循环或能否平稳回位。启用自定义表情时请提供能恢复默认值的 `neutral` 表情，避免叠加残留。

导入时移除模型动作的浏览器音频引用，页面本身也保持静音；音频统一由原生服务控制，避免绕过全局静音。模型中复制保留的音频可在互动设置里手动映射。已有音效接口、Windows TTS 和音量口型继续复用，当前不支持角色专属 TTS 音色或根据动作名称自动猜测音频映射。

## 验证

`tools/verify_characters.py` 使用真实文件系统、HTTP 服务与 Chrome，检查完整导入、资源拒绝、旧记忆迁移、记忆隔离、私有文件不可从资源路径访问，以及大肥鱼 → Haru → 大肥鱼透明渲染。

`tools/verify_characters_ui.py` 使用真实 Qt/WebEngine、文件选择器及菜单，检查导入/切换、人格与请求上下文隔离、草稿恢复、切换取消流式请求及 TTS、失败返回、拖动、清空和全局静音持久化。聊天使用本地 SSE 验收服务；TTS 使用真实系统声音但输出音量为零，不验证真实 DeepSeek 的回答或扬声器听感。

截图与结果位于 `.local/evidence/characters/`。尚未验证大量角色连续切换的长期内存占用、所有第三方模型的参数/贴图兼容性，以及多个程序实例同时编辑同一角色记忆。
